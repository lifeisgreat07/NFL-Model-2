## Stage 7.6 — the README a recruiter actually lands on

The GitHub landing page is the first thing anyone clicking this repo sees,
and it had been left behind by six stages of work. This adds the overview
section that was missing, fixes what the page was saying that is not true,
and adds a guard so the page cannot rot silently again.

### What was wrong

Four things, all found by reading the file against the tree:

1. **Line 5 pointed at `METHODOLOGY.md` for the backtest numbers. That file
   has never existed in this repository.** `src/tune_qb_shrink_k.py:5` had
   already noticed and written it down; `src/ratings_engine.py:5` and
   `src/ol_continuity.py:5` went on pointing at it anyway, and so did the
   README. Verify: `git log --all --diff-filter=A -- METHODOLOGY.md` returns
   nothing.
2. **The repo layout named `dashboard.html`.** The generated dashboard is
   `index.html`. `dashboard.html` is not in the tree.
3. **`backtest.py` was described as "(add your own copy of the full backtest
   script here)".** `src/backtest.py` exists and is what produces the table
   the README prints two sections earlier.
4. **"The dashboard regeneration script (`generate_dashboard.py`) isn't built
   yet in this repo -- the current `dashboard.html` was hand-updated."**
   `src/generate_dashboard.py` exists, is covered by tests, and runs in
   `.github/workflows/generate-dashboard.yml`. A reader following this README
   would conclude the project is markedly less finished than it is.

### What this changes

- Adds **`## For recruiters -- project overview`** immediately after the
  headline and the live-dashboard link: what the system does, then six
  things it is meant to demonstrate, each with the file to look at. It states
  plainly that the model does **not** beat the betting market, because the
  backtest table says so and a portfolio page that omits its own losing
  comparison is not evidence of rigour.
- Fixes all four items above; refreshes the layout block to the real tree;
  adds the `python -m pytest` invocation, which the README never gave.
- Repoints the two `src/` docstrings at the dashboard's Methodology page.
- Adds a closing note that Model A is not an edge against a market price.

### The guard

`tests/test_readme_accuracy.py`, 7 tests. It holds README.md to the rule
`tests/test_claude_md_freshness.py` already holds CLAUDE.md to — no naming a
path that is not there — and adds checks specific to this page. Six
bullets, seven tests: the counts bullet is two tests, one per number.

- every backticked path in the prose exists;
- every path in the repo-layout block exists, resolved through the directory
  it is indented under (a bare `config.py` under `src/` is checked as
  `src/config.py`, not as a top-level file — checking it flat would pass
  while meaning nothing);
- no file in the repository sends a reader to `METHODOLOGY.md` while that
  file does not exist. Scoped to pointer phrasings ("see"/"in"/"per") so
  that writing down *that* it never existed stays legal;
- the recruiter section precedes the model detail;
- the stated CI-workflow count and mutation-case count are compared against
  the real glob, so "six CI workflows" cannot survive a seventh being added;
- the dashboard URL in README.md and VERIFICATION.md must agree.

Two of these failed on their first run and both failures were real:
the layout check caught `docs/` and `memory/` (see below), and the
METHODOLOGY guard's only offender was **its own docstring** — the guard
matched the rule it states. That exclusion is commented in place.

### Deliberately not in this PR

The layout block does **not** list `docs/` or `memory/`. Those directories
arrive with #45, which is not merged yet; naming them here would make this
branch's own guard fail against its own tree. They get added in a follow-up
once #45 is in. I would rather ship a layout that is short than one that is
wrong.
