Methodology

Real data, real backtest, real numbers below — nothing here is estimated.

Data

294,989 plays from nflfastR play-by-play, seasons 2020–2025 (regular season). Filtered to pass/rush attempts with valid EPA (209,559 plays) for the rating system.

Rating System — Opponent-Adjusted, Recency-Weighted

For every team, at every point in time, we fit a two-way fixed-effects ridge regression: play-level EPA regressed on offense-team dummies + defense-team dummies, using only plays strictly before that point. Each play is weighted by exponential recency decay. This means a team's offensive rating already accounts for the strength of every defense it faced — not a raw average.

play_epa ~ ridge( offense_team_dummies + defense_team_dummies ) sample_weight = 0.5 ^ (games_ago / half_life) half_life = 16 games (tested 6, 10, 16 — 16 won on log loss)

Each test season trained only on strictly earlier seasons. Pooled out-of-sample results across 2022-2025 (1,087 games):

Two real upgrades since v1: tuning the ridge alpha via the same backtest process used for recency half-life found the model was over-regularized at 200 (a value picked by convention, not evidence) -- alpha=15 performs best. Separately, adding a leak-free, recency-weighted per-QB rating (trailing EPA/dropback for that week's actual starter, shrunk toward league average for small samples) was by far the single biggest improvement tested: accuracy 60.0% to 62.6%, AUC 0.605 to 0.662. The QB feature alone very nearly matches the full combined model -- a real, expected finding given how much quarterback play drives NFL outcomes. Model B still barely beats the market alone (68.1% to 68.3%) -- that gap hasn't closed much, which is an honest result, not a disappointing one.

Known Gaps

01Ridge regularization strength (alpha=200) was set by convention, not tuned via backtest like the recency half-life was -- a real gap given the "don't set constants arbitrarily" rule this project runs on
02No QB-specific features yet -- the model can't see that Arizona is starting a backup/rookie situation, which is why Model A and the market diverge sharply on that game
03No injury, weather, or rest/travel features implemented despite being in the original spec
04Gradient boosting was tested and did not beat logistic regression at this feature-set size -- worth revisiting once more features exist

Weekly Re-run Process

  1. Add the completed week's real plays to the training data
  2. Refit team ratings at the new "as of" cutoff
  3. Pull that week's Vegas lines for Model B
  4. Generate both models' predictions for the upcoming week, save before kickoff
  5. Grade last week's saved predictions against actual results
