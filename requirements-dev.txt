# Test-harness dependencies. Pinned, and deliberately kept out of
# requirements.txt.
#
# Why a separate file: requirements.txt is this project's reproducibility
# record -- the exact versions that produced the published backtest baseline
# and every number on the dashboard. pytest produces none of those. Folding it
# in would blur what that pin certifies, and it would drag a test-only
# dependency into the pandas/numpy constraint discussion that file is already
# carefully explaining.
#
# Why pinned anyway: Booth re-runs this suite to verify a PR's claims
# (.github/workflows/booth-pr-audit.yml). An unpinned pytest means the version
# that audited one PR and the version that audits the next can differ, with
# nothing in the repo recording which was which. That is the same
# unverifiable-claim problem the runtime pins exist to prevent, relocated into
# the verifier -- which is a worse place for it.
#
# Install both:  pip install -r requirements.txt -r requirements-dev.txt

pytest==9.1.1

# The linter run-tests.yml runs, with the rules ruff.toml selects (Stage 27).
# Pinned for the same reason: a new ruff release can add findings to a rule,
# and a PR should not go red because the linter changed under it.
ruff==0.16.9

# The type check run-tests.yml runs over the weekly run's two core modules
# (Stage 35). Pinned for ruff's reason: a new mypy release can add errors.
mypy==2.3.1

# Property tests, tests/test_properties.py (Stage 48 item 16). Pinned for
