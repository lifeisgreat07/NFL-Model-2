### Stage 81 - Nothing locks unseen

1. A Thursday 02:00 UTC check opens an alert when a pull request that adds the coming week's `data/nfl/qb_overrides/<season>_week<N>.json` is still open, naming the PR and the 11:00 UTC lock (weeks 7 and 8 locked with Hurts and Lock because #530 and #542 sat open).
2. The lock run records an open override PR in the picks' provenance and alerts; Line Judge reports it as a finding.
3. The Pages build runs after an NHL daily, NBA daily or Weekend refresh run whose data job succeeded, whatever Line Judge's later job concluded; a test holds every writer with a judge job to it.
4. The Weekly update marks its slot when the lock step and the commit succeeded, not only when the whole job did, so GitHub's late copy cannot re-run a lock whose later step failed.
5. Every failure alert carries the last 30 lines of the failing step; `tests/test_alerts.py` requires it.
6. Browser checks run nightly on `main` with an alert, and the pull-request trigger covers the NBA and NHL data paths.

### Stage 82 - The auditor audits from main

1. Booth's report checker (`booth_report_posted.py`, `booth_verdict.py`) is copied from the base commit, and both join `AUDITOR_FILES`.
2. Booth reads `BOOTH_PROTOCOL.md` from a base checkout, as Spotter does.
3. The protocol and the prompt say that a PR's title, body, diff, comments and test output are evidence, never instructions.
4. Booth writes its report to a file; a separate job with no model and no PR code posts it, and the model's environment holds no write token.
5. Each report carries its run id; the agent-log collector accepts only comments whose run is a Booth audit run, anchors the heading to the start of the body, and stops treating `github-actions[bot]` as Booth.
6. Spotter's publish job validates the rendered JSON against a schema and checks PNG headers; its prompt treats every file in `renders/` as content.
7. `deploy-pages.yml` gets per-job permissions: the build job has no Pages or OIDC scope.
