## Decided

- **Stage numbers stay frozen; `docs/context.md`'s "Stage 11" is renamed to
  Stage 9 rather than Stage 11 being defined in CLAUDE.md.** The work it
  labelled is Stage 9's own text — amber disambiguation, the diverging pair
  through the validator — so defining it would duplicate Stage 9's scope under
  a second number, which is exactly what the freeze exists to prevent. Two
  source docstrings renamed with it so the claim survives a `git grep`.
- **The template's `--series` tokens are canonical, not the Stage 8 mocks'.**
  The doc described `--series-a/-b/-m/-p` at colours the page has never used.
  The port deliberately kept the dataviz validator's palette, and the mock
  palette fails six of `tests/test_dashboard_charts.py`'s assertions when
  measured. The doc now records the decision instead of contradicting it.
- **The listbox departs from the week stepper on one point, deliberately.**
  The stepper hardcodes `visually-hidden` on its select, which is safe because
  its arrows are static markup. The listbox is built entirely by script, so its
  select ships visible and `enhanceSelect` hides it after the list exists —
  otherwise a no-script reader gets no control at all.

## Surprised us

- **CLAUDE.md itself was wrong in ways that were costing sessions.**
  `--shadow-overlay` was documented in two files as having one consumer, the
  `.overlay` component — `.overlay` appears zero times in the template; it was
  a mock-only element, and the real consumers are `.undo-toast` and `.rel-tip`.
  `.bnav-item`, named in the two-navigations trap, has never existed in the
  repo. The jargon guard's `TECHNICAL_PAGES` is four pages, not the three
  listed. "Roughly 704 tests assert on the template" was the whole suite that
  day. "This line read 174 for three days" was about a day by this file's own
  git history. Stage 3 was still headed IN PROGRESS with a "still to do" item
  that had landed fourteen minutes after the sentence was written.
- **A comment is not a description.** #69 grew commits after its body was
  written; the head move was documented in a PR comment, and
  `scout_preflight.py`'s `scope disclosed` check reads the description, as does
  Booth. The comment changed nothing and the preflight job went red.
- **Four audits on #69, four findings, none of them in the code.** An
  undisclosed commit, then three suite figures where the check allows one, then
  a clause claiming one file was touched by both sides of a merge when two
  were. Each cost a manual edit by the only person who can make one.
- **A guard whose fixture fails reports as WRONG-GUARD, "Failures: none
  reported", and blames a healthy guard.** pytest calls a setup failure an
  ERROR; the mutation runner reads failures.
- **Three matchers in one session captured the wrong text**, each producing a
  confident wrong failure message — one found the CSS rule declaring a class
  and ran 50,000 characters to the next `</svg>`, sweeping up the very hex it
  was written to prove absent.
- **A measured figure attached to the wrong cause, twice, by two different
  agents.** A probe showed document height changing 129-559px per pick tap; it
  was team logos 404-ing offline and `onerror` hiding them. Booth's own first
  run of the same probe showed 548-926px of scroll, which was its test
  auto-scrolling an off-screen element before tapping. Both were caught by
  checking rather than by trusting.
- **Booth reproduced the original bug against `main` unprompted** to prove #70
  was a behavioural fix rather than assertions on unchanged code. On `main` the
  tapped button is destroyed; on the branch it survives. Nobody asked it to.
