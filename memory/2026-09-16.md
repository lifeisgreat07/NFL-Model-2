  rather than argued in prose: drop the `Sort: ` prefix AND freeze the button
  at its longest label. Alternatives were a fixed width alone (still three
  lines at 390px) and shorter labels alone (button still resizes). Mark picked

  identical.

  Kept under the repo's own rule for that case: state it as a function, check
  it over synthetic geometries and over the rendered page.
- **The colour sweep lives in `tests/test_dashboard_charts.py`, not a new
  module.** That file owns the OKLab ruler. A third home for colour maths is
  how the metric confusion below happened in the first place.
- **`ACCEPTED_CLOSE` lands holding every current violation**, on the
  plain-language allowlist's pattern, with "not traced" said explicitly so it
  cannot be misread as a clearance. Shrinking it is the definition of done.
- **`--good` vs `--warn` is NOT a defect** despite collapsing under CVD. The
  graded tag prints "Correct"/"Missed" and Team Deep-Dive's `mark()` prints

## Surprised us

- **A missing webfont turned a real defect off.** The first reproduction ran
  from `file://` with Google Fonts blocked and found no overflow at all — the
  fallback face is narrower, and the list landed 9px inside the edge. Same
  commit, same viewport, wrong typeface, opposite answer. Fetching the real
  woff2 files and serving them locally reproduced it at +41px. A fallback font
  does not merely shift a text-width figure; it can flip a yes/no.
- **`document.fonts.check()` returns true when the font is absent entirely.**
  It answers "is anything still pending", not "is this font loaded". It was
  used as the gate on three measurement scripts before that was noticed. The
  numbers survived only because a separate comparison — 218px with the webfont
  against 205px without — showed the two environments really did differ.
- **Two mutations SURVIVED a brand-new guard, for the second time in two
  days.** Both because today's data reaches only one branch of the rule: every
  close pair is already accepted and no entry is stale, so "report an
  undocumented pair" and "report a stale entry" had no input. An allowlist that
  covers everything makes its own interesting branch unreachable.
- **A guard failed through its fixture rather than its assertion.** A size
  sanity-check on the extracted `lbxFlipDecision` required more than 200
  characters; the mutation that deletes a branch made it shorter, so the
  fixture errored at setup and the runner reported WRONG-GUARD, "Failures: none
  reported", against a perfectly healthy guard.
- **Booth asked for a spot-check it could not do itself** — its sandbox had no
  browser, so all four UNVERIFIABLE claims were pixel figures. Re-running them
  in my own sandbox would have been a second sample of one condition, so they
  were re-measured on markys through the built-in browser instead: `--lbx-fit`
  218px on both machines, all six options equal, no list past the viewport.
