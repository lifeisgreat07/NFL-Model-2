# 2026-09-12

Four PRs merged, all of them surface work on the two `.game-card` render
paths. The suite went 918 -> 1044 and the mutation corpus 24 -> 28 files
(147 cases). The remote went from sixteen branches to one.

## Shipped

- **#64 — one matchup title, built in one place.** `matchupHeader(g, variant)`
  replaces the hand-built title in both `renderGames()` and
  `renderPicksGrid()`. Appearance deliberately preserved and measured
  before/after, because the `@` separator surviving on My Picks after being
  changed everywhere else is exactly what two render paths cost.
- **#65 — the Week Board opens in kickoff order.** `kickoffKey()` builds a
  STRING key (`gameday` + `T` + `gametime_et`), never a `Date`, so the
  reader's timezone cannot contaminate an Eastern time. Comparators live at
  module scope so the suite can execute them.
- **#65 also — `src/backfill_game_dates.py`.** Week 1's saved records had no
  date. Adds the three schedule fields only, never modifies one, reports
  disagreements and unmatched records, and has a `--check` mode.
- **#66 — one week control, used by both pages.** `syncWeekStepper` and
  `wireWeekStepper` take a prefix; My Picks' bare native `<select>` becomes
  the Board's stepper. `showSharedPicks()` syncs explicitly because it must
  not dispatch `change` — that handler ends the shared view it is opening.
- **#67 — the pick card says which game, when and who.** Kickoff line, 36px
  team logos above the abbreviations, the track-record block removed from My
  Picks (it still renders twice on the Board), Model B's decision kept.
- **Branch cleanup.** Fifteen merged branches deleted from the remote and
  locally, each checked with `git merge-base --is-ancestor` first, the script
  set to abort the whole run if any single check failed.

## Decided (with the reasoning)

- **Week 1 WAS backfilled, reversing the decision recorded the same morning.**
  `docs/context.md` said "DECIDED: no backfill, do not re-open this" on the
  premise that the week was over. It was not — 2 games played, 13 on Sunday,
  1 on Monday. Once the week was live, a dateless week 1 beside every dated
  week stopped being cosmetic. The lesson is not about the backfill: a
  decision recorded without its premise cannot be re-checked when the premise
  changes, and "do not re-open this" is what stops anyone looking.
- **Broadcast channel is not deferred, it is unsourced.** `load_schedules()`
  returns 46 columns and not one is a network. It needs a new feed with its
  own staleness story, and a flexed game changes network days before kickoff,
  so it needs a refresh policy rather than a one-time fetch. Stage 6, not a
  line of markup. Said in #67's body rather than left for someone to notice
  the request was three-quarters filled.
- **A figure in a PR body should name the commit it was measured at.** Booth
  proved this works: #66's body said "Measured at `4f76432`", and when the
  branch later merged `main`, Booth built a worktree AT THAT COMMIT and
  confirmed all of it rather than reporting stale numbers. Scoping is what
  keeps a figure true when the base moves.
- **Stack onto `main`, not onto an open PR, whenever the work allows.** The
  picks-card branch was cut from an open PR and dragged four already-merged
  commits into its diff. Cherry-picking the one commit onto `main` produced a
  6-file diff instead of a 15-file one, and the two PRs then merged in either
  order with a single-digit README conflict.

## Surprised us

- **A number appeared in an evidence section that no command had produced.**
  #67's body claimed the pre-PR tap target was `163x62`; it was `163x41`.
  Booth caught it. The 88 was measured, the 62 was not, and it could not be
  traced to any run. It also understated the improvement (+47px/+115% became
  +26px/+42%), which is the tell: a fabricated figure does not lean in your
  favour, it lands anywhere. Quoting a WIDTH was wrong too — `.pick-btn` is
  `flex:1`, so width follows the viewport and only height is a property of
  the change.
- **Booth's environment is not consistent between runs.** #67's audit drove
  headless Chromium; #66's, an hour later, had no browser at all and returned
  UNVERIFIABLE for the same class of claim, falling back to CSS box-model
  arithmetic. A render claim may or may not be checkable depending on which
  runner picks it up.
- **A green suite does not prove a mutation corpus still works.**
  `test_every_anchor_still_matches_exactly_once` proves each `find` string
  still RESOLVES. Only running the mutations proves each is still caught by
  the guard that names it rather than surviving or firing a different test.
  After merging two branches that both touched the same file, all 147 were
  run individually.
- **The Board was sorted by a fact it did not display.** #65 ordered the cards
  by kickoff; #67's first cut put the kickoff line on My Picks only. Nothing
  errored, every test passed, and the only symptom was the owner asking why
  one page had the date and the other did not.

- **The wrap-up broke the start-up.** Rewriting `docs/context.md` put a real
  arrow (`→`) in it. `src/session_start.py` prints that file verbatim, and
  a redirected stdout on Windows is cp1252, which has no arrow — so the first
  command of every session died with a `UnicodeEncodeError`, several screens
  in, after looking perfectly healthy. Found only because the last act of the
  session was to run the thing being handed over. `tests/test_session_start.py`
  pinned `PYTHONIOENCODING=utf-8` at both ends, which is exactly why it never
  caught this: **the fixture was more careful than the environment it stood in
  for.** Fixed by reconfiguring the stream in the tool, not by banning
  characters from the document — a rule enforced by nothing, in a file anyone
  edits, is not a fix. The new guard runs it under `cp1252` on purpose, and
  the arrow stays in `context.md` so the test has a real case to exercise.
