## Decided

- **`src/session_wrapup.py`'s date checks get one-directional slack: tomorrow
  passes, yesterday does not.** Booth found the gate and the pytest guard
  disagreeing — the guard tolerated a stamp one day ahead, the gate demanded an
  exact match. Both directions were considered. Symmetric slack is the easy fix
  and the wrong one: the forward day is a timezone, the backward day is a file
  nobody rewrote, and the backward case is the only thing the check was ever
  for. `tests/test_wrapup_date_slack.py` asserts both directions so a future
  edit cannot quietly widen it.
- **The README's numeric claims are checked against the thing they count**, not
  restated. "Six CI workflows" is compared to the real glob. The alternative —
  a second copy of a number — is the exact failure this repository has already
  had three times.
- **`docs/context.md` is stamped on UTC, deliberately**, because the agent
  writing it runs there and the forward slack above makes that valid on the
  machine too.

## Surprised us

- **A green check on a Booth run does not mean the audit passed.** The workflow
  succeeds whenever Booth manages to post a report; the verdict lives in the
  comment text. #45's third audit was green in Actions and read NEEDS HUMAN
  REVIEW with four discrepancies. Worth knowing before trusting a checkmark.
- **The `edited` trigger on `.github/workflows/booth-pr-audit.yml` fires only
  for the PR *description*, and its `if:` guard requires
  `github.event.changes.body`.** Editing a *comment* fires `issue_comment`,
  which that workflow does not listen to, so nothing starts and nothing says
  why.
- **`METHODOLOGY.md` has never existed in this repository.** Three files told
  the reader to see it, including the README's fifth line.
  `git log --all --diff-filter=A -- METHODOLOGY.md` returns nothing.
  `src/tune_qb_shrink_k.py` had noticed and written it down; nobody acted on it.
- **The new README guard's first run flagged its own docstring.** The rule bans
  pointer phrasings naming that file, and the file stating the rule necessarily
  contains one. Third time this session that a guard has matched itself.

- **`run-tests.yml` was red on every PR for days and nobody looked**, because
  `booth-pr-audit.yml` ran the same suite green on the same commit and Booth is
  the job that gets read. Cause: `actions/checkout` defaults to `fetch-depth: 1`;
  sixteen tests here read real git history and skip without it, and
  `test_scout_preflight.py`'s exit-code test built its fixture from the last
  three non-merge commits, found one, and failed on its own empty fixture.
  Reproduced with `git clone --depth 1` before and after. Fixed both halves:
  the workflow asks for full history, and the test skips rather than fails.
  Committed straight to `main` rather than as a third PR, because a third audit
  was not affordable and the fix makes a red light truthful.
- **Both branches added `.pr-body.md` to `.gitignore` independently**, which is
  what #46's merge conflict was. Kept the longer comment.

- **Season Accuracy rested on one week of the PREVIOUS season.** A page headed
  "Season Accuracy", read in September 2026, reported 2025 Week 10 as the
  season's record — because 2026 Week 1 was graded before it was played, so an
  empty week rendered as "0/0" and gave the trend chart a second point. Three
  flat lines that looked like a finding. Found by opening the published page,
  not by reading the template.
- **The betting-line sentence shipped inverted on all sixteen cards.**
  `spread_line` is positive when the HOME team is favoured; the card displays it
  negated, football-style. "The betting line agrees" reads exactly as well as
  "disagrees" — grammatical, plausible, invisible in the diff. Caught only
  because the sentence contradicted the card's own Vegas line two inches above.
  The convention was **already written down** in `tests/team_dive_harness.js`.
  Got it wrong by assuming instead of reading.
- **The model is overwhelmingly a quarterback model.** QB contributions run about
  an order of magnitude above offense and defense (0.99 against 0.04 on one
  card), so nearly every board card says "almost entirely on the quarterback
  matchup". That is the model showing through, not a stuck template. Said so in
  the onboarding banner rather than varying the phrasing to hide it.
- **Renaming a toggle left three references behind** — its own reset label, the
  onboarding banner, and a Methodology paragraph. Same shape as the mobile nav
  still listing Playoff Odds after that page was deleted.
- **`95% CI` had been on a reader-facing page the whole time.** The jargon guard
  banned "confidence interval" spelled out and had never seen the abbreviation.

## Left open

- **A visual reference for Stage 8 — the blocker.** Two candidates were assessed
  today and both set aside. `basbruss/Minimalist-Dashboards` turned out to be a
  Home Assistant Lovelace configuration: YAML plus HACS custom cards, last
  released February 2023, with no CSS or components to lift. Its *look* (soft
  tiles, muted palette, icon-led, generous whitespace) is a fair mood reference;
  its code is not usable at any effort. The second option — shadcn/ui with
  Tremor or v0 — is React throughout (Tremor was acquired by Vercel and is
  React + Tailwind + Radix), so adopting it literally means replacing this
  dashboard's architecture, not restyling it. **The recommendation given:** take
  shadcn's token layer (neutral scale, radius, border and shadow discipline,
  spacing rhythm) into the existing plain CSS, use v0 as a design *generator*
  whose output is translated rather than imported, and keep the hand-built SVG
  charts — they already do things a chart library would lose (colour follows the
  entity so a filter cannot repaint survivors; shape and dash carry identity
  without colour; dark mode stepped rather than flipped). Also flagged: shadcn
  is now the default look of a great many dashboards, which is a real cost for a
  portfolio piece whose pitch is independent judgement.
