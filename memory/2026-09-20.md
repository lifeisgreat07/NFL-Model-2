## Decided

- **The verifier is standalone, not a suite test.** No CI job here has a
  browser and Playwright is not on `markys`. What the suite CAN check is the
  premise — each "cannot meet" token still has exactly one consumer, in the
  place the verdict names — so that is what was guarded. The co-occurrence
  findings themselves have nothing recomputing them, and that gap is written
  down in `docs/context.md` rather than papered over.
- **The README wording defect was NOT fixed on this branch.** Bumping the
  count is forced by the new case file; fixing "cases" to mean what the guard
  counts moves the guard's own regex, which is a second item. Recorded in the
  PR description so the choice is visible rather than missed.
- **The premise rule is a plain function checked over synthetic sources.** On
  today's template every branch but "the premise holds" is unreachable, which
  is exactly the arrangement that let two mutations survive on 2026-09-16.

## Queue item 1 investigated, and refuted

Started the `#8A93A8` item and stopped before writing a fix, because the
premise fails twice over.

- **The chevron never paints.** All four elements wearing `.week-select` are
  clipped to 1x1 with `clip-path: inset(50%)` in the rendered page.
  `enhanceSelect()` adds `.visually-hidden` to `#sort-select` and
  `#teamdive-select`, which do not carry it in markup. Measured across all
  nine pages, both themes.
- **The no-JS reader the markup-visible selects exist for cannot reach
  them.** `tests/mutation/cases/listbox.json` states the reason plainly:
  with JavaScript off there would be no sort control. But with JavaScript off
  there are no table rows, no game cards, no charts, and the nav buttons are
  inert `<button>`s, so only Power Ratings is ever on screen and both selects
  live on pages nobody can reach. No `<noscript>`, no `:target` CSS.
- **Sizing does not depend on it either.** `fitWidest()` measures a detached
  clone of the BUTTON appended to `<body>`, not the native select — checked
  because it was the one plausible unrecorded reason for the markup choice.
- **`teamColor()`'s fallback is reachable only for an abbreviation outside
  the 32 in `TEAM_COLOR`**, and its only caller is `matchupColors`, whose only
  consumer is the Week Board card's split bar — the thing Stage 8's "team
  identity is a logo, never a colour" may retire wholesale.

Proposed and not yet done: correct the reasons in CLAUDE.md, the two
`listbox.json` `why` fields and `tests/test_listbox.py`'s docstring; leave the
guards themselves alone, since "hidden by script, not by markup" is still a
fine default; and add a `<noscript>` note, because a JS-blocked stranger
currently gets an empty table and no explanation, which is a poor first
impression for a portfolio piece.
